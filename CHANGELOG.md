# Audit & Repair Changelog — Windows vs Linux Academy

Repair performed after a full-app audit. Method per issue:
Inspect → Reproduce → Root cause → Fix → Test → Verify → Regression test.

## BUG-001 — Production build completely broken
- Area: Build / `src/pages/os-report.tsx`
- Problem: `next build` failed; `HorizontalBar` is not exported by
  `react-chartjs-2` v5 (removed in Chart.js v3+).
- Root cause: Stale import from an older chart API.
- Fix: Removed `HorizontalBar` import (horizontal bars are rendered with
  `Bar` + `indexAxis: 'y'`, which `memoryData` already uses). Also removed
  unused icon imports, unused `useEffect` import, and dead `categoryWinners`
  dataset. Made the cover heading responsive (`text-3xl md:text-5xl`).
- Verification: `npx tsc --noEmit` PASS, `npm run build` PASS (27/27 pages),
  `npm run lint` PASS, `/os-report` returns HTTP 200.
- Status: FIXED

## BUG-002 — Dynamic Tailwind classes silently produced no styling
- Area: Styling / `index.tsx`, `learning-hub.tsx`, `os.tsx`,
  `os-overview.tsx`, `windows.tsx`
- Problem: Template classes like ``border-${color}-500`` /
  ``text-${color}-500`` / ``bg-${color}-500`` are never generated by the
  Tailwind JIT compiler, so card borders, icon colors, and timeline dots
  rendered unstyled.
- Root cause: Dynamic class-name construction (documented Tailwind pitfall).
- Fix: Replaced every instance with explicit static lookup maps
  (`borderFor`, `textFor`, `topicStyles`, `timelineDot`).
- Verification: `grep` for ``${`` in class names returns only explanatory
  comments; build PASS.
- Status: FIXED

## BUG-003 — `text-muted-foreground` class did not exist
- Area: Styling / `tailwind.config.js`, `src/styles/globals.css`
- Problem: `text-muted-foreground` (shadcn-style token) is used on ~20
  files but was never defined, so muted text fell back to body color.
- Root cause: Missing theme token.
- Fix: Added `muted.foreground` (`#64748b`) to Tailwind colors plus a
  dark-mode override (`#94a3b8`) in `globals.css` for contrast.
- Verification: Build PASS; class now generated in CSS bundle.
- Status: FIXED

## BUG-004 — Tablet hamburger menu opened nothing
- Area: Navigation / `src/components/common/Navbar.tsx`
- Problem: On `md–lg` screens the hamburger toggled `menuOpen`, but the
  dropdown was `md:hidden`, so nothing ever appeared and 3 nav links were
  unreachable on tablets.
- Root cause: Breakpoint mismatch between toggle visibility and menu.
- Fix: Dropdown is now `lg:hidden` (works for mobile + tablet); added
  `aria-label`/`aria-expanded` to toggles; logo text now shows on all sizes.
- Verification: Manual breakpoint review; all 9 links reachable.
- Status: FIXED

## BUG-005 — Search icon invisible, search page non-functional
- Area: Search / `SearchBar.tsx`, `src/pages/search.tsx`
- Problem: `<i class="fas fa-search">` with no Font Awesome loaded (empty
  button); results page always showed "No results found (demo)"; `q` array
  type unhandled; no empty/loading states.
- Root cause: Missing icon dependency + stub implementation.
- Fix: `FaSearch` from react-icons with label; real client-side search over
  a 24-page site index with result counts, empty-query guidance, no-result
  state, and `aria-live` announcements.
- Verification: `/search` and `/search?q=linux` return HTTP 200.
- Status: FIXED

## BUG-006 — Contact form reloaded page, no validation, dead links
- Area: Forms / `src/pages/contact.tsx`
- Problem: No `onSubmit` handler (submit reloaded the page and lost input);
  no labels/validation/error or success states; social icons used dead
  `href="#"` links.
- Root cause: Uncontrolled stub form.
- Fix: Controlled inputs with inline validation (name/email format/min
  message length), `role="alert"` errors, loading + success states with
  reset, proper `<label>`s, real external social URLs + `mailto:`.
- Verification: `tsc` + build PASS; `/contact` HTTP 200.
- Status: FIXED

## BUG-007 — Quiz accepted empty submits, no answer review
- Area: Forms / `src/pages/quiz.tsx`
- Problem: "Submit" worked with zero answers; no per-question feedback, no
  correct-answer display, no retry.
- Root cause: Missing completion guard and review UI.
- Fix: Submit blocked until all questions answered (with count + alert);
  post-submit green/red highlighting, correct answers shown, score message,
  "Try again" reset, `aria-pressed` and disabled state after submit.
- Verification: Build PASS; `/quiz` HTTP 200.
- Status: FIXED

## BUG-008 — Terminal `ls -l` broken, state mutated, history keys wrong
- Area: `src/pages/terminal-simulator.tsx`
- Problem: `ls -l` treated `-l` as a path ("Directory not found");
  `mkdir`/`touch` mutated state in place without `setFilesystem` (unreliable
  renders); Up/Down history used an inverted index; quick-command buttons
  left stale input; clipboard errors unhandled; icon-only buttons unlabeled.
- Root cause: Flag/path conflation, direct nested-state mutation, off-by-one
  history logic.
- Fix: Flag parsing separated from path; immutable `setFilesystem` updates;
  corrected history navigation (`-1` = fresh input); quick commands execute
  + clear + refocus; clipboard `try/catch`; click-to-focus; labels/aria;
  removed unused icon imports.
- Verification: `tsc` + build PASS; `/terminal-simulator` HTTP 200.
- Status: FIXED

## BUG-009 — Theme toggle hydration mismatch
- Area: `src/components/common/ThemeToggle.tsx`
- Problem: Read `theme` (undefined on first render) causing a server/client
  mismatch flash and wrong icon.
- Root cause: No mount guard.
- Fix: `mounted` guard + `resolvedTheme` with dynamic `aria-label`.
- Verification: Build PASS.
- Status: FIXED

## BUG-010 — Rating bars crushed on mobile
- Area: Responsive / `src/pages/comparison.tsx`
- Problem: `grid-cols-4` with nested 3-column bars squeezed labels and bars
  unreadably on phones.
- Root cause: No responsive stacking.
- Fix: `grid-cols-1 sm:grid-cols-4` with bars collapsing below `480px`.
- Verification: Build PASS; layout review.
- Status: FIXED

## BUG-011 — No custom 404, no SEO defaults
- Area: Routing/SEO / `src/pages/404.tsx` (new), `Layout.tsx`
- Problem: Unknown routes showed the default Next 404; no page `<title>` or
  meta description anywhere.
- Root cause: Missing files.
- Fix: Added branded 404 page with recovery links; default `<Head>` title +
  description in `Layout`; `min-w-0` on `<main>` to prevent flex overflow.
- Verification: Unknown route returns HTTP 404 with "Page not found" body.
- Status: FIXED

## BUG-012 — `npm run lint` had no config; deprecated image config
- Area: Config / `.eslintrc.json` (new), `next.config.js`
- Problem: Lint prompted interactively (unusable in CI/build); `images.domains`
  deprecated in Next 14.
- Root cause: Missing/deprecated config.
- Fix: Added `extends: next/core-web-vitals`; migrated to `remotePatterns`.
- Verification: `npm run lint` → "No ESLint warnings or errors"; lint errors
  for unescaped `'`/`'` entities in 4 pages fixed with entities.
- Status: FIXED

## BUG-013 — Case-sensitive command filter, no empty state
- Area: `src/pages/commands.tsx`
- Problem: Filter was case-sensitive and showed a blank list on no match.
- Root cause: Raw `includes(filter)`.
- Fix: Case-insensitive trimmed matching, labeled `type="search"` input,
  live result count, and a no-match empty state.
- Verification: Build PASS; `/commands` HTTP 200.
- Status: FIXED
